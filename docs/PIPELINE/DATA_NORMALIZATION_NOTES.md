# DATA NORMALIZATION NOTES

[scripts/normalize-data](/scripts/normalize-data.ts)

## PRODUCT TYPE FILTER

Normalization discards products early (so they never appear in `data/normalized/**` or downstream `data/aggregated/**`) when:
- `product_type` is non-empty, and does **not** contain `mat`/`mats`, and
- the product title/tags also do **not** contain `mat`/`mats`.

This is primarily to prevent non-mat catalog items (e.g. apparel like leggings) from entering the dataset even if they appear in a `products.json` feed.

Note: `Yoga Rug` / `Yoga Rugs` are treated as relevant and will pass this gate.

Also discarded: obvious multi-packs (e.g. `Box of 7`, `Pack of 6`) to prevent wholesale listings from polluting series groupings. Multipack detection intentionally ignores `body_html` to avoid false positives from unrelated copy (“set of 2…”).

## SCRAPING ENABLED FILTER

Fetch writes `data/raw/{date}/_brands.json` (including each brand’s `scrapingEnabled` flag). During normalization, if that metadata file exists, we only process raw brand files whose `scrapingEnabled !== false`. This prevents stale raw files (e.g. pulled from CI) from accidentally leaking disabled brands into `data/normalized/**` and downstream outputs.

Fetch also removes any existing `data/raw/{date}/{brand}.json` files for brands that are not enabled (either `scrapingEnabled=false` or not present in the Convex brand list) so today’s raw folder reflects the current source of truth.

## PRODUCT EXCLUSIONS (REMOVE FLAG)

YogaMatLabApp can maintain a dedicated “remove”/exclusion list for products that should never enter the dataset (e.g. apparel products that slipped into a Shopify feed). During `npm run fetch`, YogaMatLabData will try to load exclusions from Convex and save them to `data/raw/{date}/_product-exclusions.json`. During normalization, any product whose `(brandSlug, shopifyId)` matches the exclusion list is skipped.

Supported sources (merged):
- `data/raw/{date}/_product-exclusions.json` (generated by fetch when the Convex query exists)
- `config/product-exclusions.json` (optional manual fallback; committed)

Convex query name defaults (first one found):
- `productExclusions:getActive`
- `productExclusions:getForPipeline`
- `productExclusions:listActive`

Or set `CONVEX_PRODUCT_EXCLUSIONS_QUERY` to the query name you implement in YogaMatLabApp.

## SERIES (DESIGNS AS PRODUCTS)

Some brands publish the “same mat” as many separate Shopify products (one per design/colorway), instead of variants. Normalization derives optional grouping fields:

- `seriesKey` / `seriesName` (stable group identifier + display name)
- `designName` (the design/colorway portion, when detectable)
- `seriesConfidence` / `seriesVersion` and `designConfidence` / `designVersion`

This enables YogaMatLabApp to show one card per series and list “designs available” without storing full variant combinations.

Aggregation also produces `data/aggregated/**/brand-series-index.json`, which groups products by `seriesKey` (or a stable fallback) and unions key fields like `designNames`, `availableColors`, price ranges, and index-friendly dimension arrays.

## PRICE CURRENCY NORMALIZATION

Shopify `products.json` does not include currency per-product. YogaMatLabData assumes a brand-level price currency and converts non-USD prices to USD during normalization.

- Brand currency mapping: `config/brand-currency.json` (`brandCurrency: { [brandSlug]: "MYR" | ... }`)
- Offline FX rates: `config/exchange-rates.json` (`usdPerUnit`, used as `priceUsd = price * usdPerUnit[currency]`)
- Optional overrides: set `YML_FX_USD_PER_<CURRENCY>` (e.g. `YML_FX_USD_PER_MYR=0.215`)

When conversion happens, the normalized output keeps `minPrice`/`maxPrice`/`variantPriceValues` in USD and stores the original currency/values in `priceCurrencyOriginal` / `*Original` fields for traceability.
